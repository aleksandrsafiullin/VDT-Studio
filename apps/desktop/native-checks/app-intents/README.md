# macOS App Intents prototype

The native prototype defines five foreground actions for supported macOS versions. Apple’s extractor recognizes the actions both in a framework with an application package dependency and when compiled directly into a signed fixture app’s main executable. The macOS qualification packager now links the Swift code and stages extracted metadata before signing. Signed installation and Shortcuts discovery still need qualification.

| Action | Effect |
| --- | --- |
| Open VDT Studio | Brings the ordinary app interface forward. |
| Show VDT Voice Controls | Opens the voice controls for the current scope. Capture starts only through the existing in-app control. |
| Show VDT Status | Returns one fixed status dialog for the current scope. |
| Request to Stop VDT Listening | Opens the confirmation control for the exact active voice session. |
| Open Pending VDT Review | Opens the exact pending review in the owning window. Approval stays with the existing visual review. |

The App Intents have zero parameters and require local device authentication. The main application is the only explicit execution target on macOS 27 and later. The runtime requires separate consent and a current scope for scoped actions. An ephemeral ticket authorizes one result and expires after five seconds. The owning UI checks the presentation again at dispatch against the consent epoch, active scope and exact capture or review token. The dialog set exposes fixed status text. Graph names, content, capabilities, IDs, audio and approval payloads stay in VDT Studio.

On macOS, Shortcuts supports these App Intents actions in user-created shortcuts. A user can ask Siri to run a shortcut already in their collection. Apple’s macOS guidance excludes developer-provided App Shortcuts, so this prototype declares only actions. Processing for a Siri request remains subject to the system’s behavior and requires observation on the qualified installation. [Apple App Shortcuts guidance](https://developer.apple.com/design/human-interface-guidelines/app-shortcuts) · [Run a shortcut with Siri](https://support.apple.com/guide/shortcuts-mac/run-shortcuts-with-siri-apd07c25bb38/mac)

## Run the compiler and boundary checks

Pass an existing empty evidence directory to `check-app-intents.sh`. The check compiles the boundary tests and extracts App Intents metadata with the active macOS SDK. The tests cover opt-in, action allowlisting, status, forged, replayed, expired and stale tickets, exact review and capture scope, consent changes before delivery, and the application metadata package dependency. The checker also compiles a standalone fixture app with a macOS 14 deployment target, places its extracted metadata in the bundle’s Resources directory, signs the app with the hardened runtime and executes the five intent implementations through a synthetic in-process host. Default signing is ad hoc. An explicit `VDT_MACOS_SIGNING_IDENTITY` may select an existing Developer ID Application fingerprint for local validation without a timestamp. The checker retains logs, metadata and signature details and removes the fixture app with its compiler scratch. The actions require macOS 26 or later. The direct executable check bypasses OS invocation and leaves Launch Services, Shortcuts registration and Siri unqualified.

## Owning-window bridge

`VDTIntentNativeHost.swift` exports the availability, attach, snapshot update and detach entry points. The packaged macOS Tauri bridge accepts its private IPC command only from the `main` WebView on the authenticated loopback origin. It generates the window owner token, clears ownership on navigation and window destruction, and expires an unrenewed snapshot after three seconds. Updates carry the snapshot sequence and opaque UUIDs for consent, scope, exact capture and exact review. The native callback queues bounded presentations for that same owner. Each has its owner, sequence, one-use ID and a deadline of at most five seconds. The status intent reads a fixed label from the current leased snapshot.

The composer displays **Allow macOS Shortcuts for this window** after the native availability check succeeds. Consent starts off and expires on hide, page exit, lost ownership, or explicit opt-out. The current composer checks scope, exact capture or review, expiry and replay ID before focusing its existing control. Review focus checks the rendered proposal, run and revision. A user acts on the focused control themselves.

The Rust command compiles only in a macOS release-profile build with `app-intents-qualification`. The composer probe requires the web build flag `NEXT_PUBLIC_VDT_APP_INTENTS_QUALIFICATION=true`. The native probe also requires macOS 26 or later and all four exported Swift ABI symbols. Use `VDT_MACOS_APP_INTENTS_QUALIFICATION=true scripts/package-macos-alpha.sh EMPTY_OUTPUT_DIR GIT_REF` after physical V05 qualification. The frozen Git ref must contain this integration. Use Apple silicon, Node 24, macOS SDK 27 or later, and an available Developer ID Application signing identity. Leave `VDT_MACOS_NOTARY_PROFILE` unset. The packager sets both build flags, merges [the qualification Tauri config](tauri-qualification.json), generates the standard Tauri icons, links and checks the Swift symbols in the app executable, and stages the extracted metadata before signing. It marks the artifact `app-intents-validation-only`. The ordinary verifier rejects that marker and any staged App Intents metadata. The overlay remains outside the ordinary capability discovery directory. Test the ABI without explicit signing or OS registration using `check-app-intents.sh EMPTY_RECEIPT_DIR --abi-only`.

## Signed integration qualification

1. Build the qualification package and verify that the five Swift intent types and four ABI symbols survive release linking. Check that the signature seals the metadata under `Contents/Resources/Metadata.appintents`. [Apple runtime and framework packaging](https://developer.apple.com/documentation/appintents/configuring-the-runtime-behavior-of-your-app-intents)
2. Bind the in-process host adapter to the primary Tauri window after its packaged web UI has registered the owning composer. Keep the Swift runtime on the main actor and clear the host snapshot on window or webview teardown. The owning UI supplies opaque consent, scope, review and voice-session tokens. A review token changes with the exact proposal and revision, and a voice-session token changes with each capture. Before focusing an existing control, the UI checks the full binding against its current state. The composer’s current keyboard fallback checks trusted input and can share its focus targets with the native presentation path.
3. After physical V05 qualification, build a Developer ID candidate containing the integrated app principal and metadata. Verify signed app and embedded frameworks, then inspect the five actions in Shortcuts from a clean profile. Exercise cold and warm app invocation, consent, revocation, window and scope changes, current and replaced voice sessions, and current and stale review. Confirm that the commands only present controls and the status dialog uses fixed text. Use a separate observation for actual Siri and offline behavior.

Until then, the normal in-app voice and review controls remain the available local path.
