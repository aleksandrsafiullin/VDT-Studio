# Приёмка открытой альфы

[План выпуска](../../docs/OPEN_ALPHA_PLAN.md) · [Запросы](requests.md) · [Эталоны для проверки](oracles.md)

Codex или Cursor выполняет проверки в интерфейсе VDT Studio и сверяет результат. Исполнителя проверки и провайдера, выбранного внутри VDT, запишите в отдельных полях.

```text
Открой eval/open-alpha/README.md. Выполни назначенные кейсы в тестовом профиле VDT Studio.
Передавай агенту VDT только текст кейса из requests.md и указанный исходный файл.
Проверь сохранённое дерево и эталоны после завершения. Для каждой попытки
зафиксируй PASS, FAIL, BLOCKED или SKIP, приложи наблюдения и фактический результат.
```

## Подготовка и запись результата

1. Зафиксируйте коммит, версию приложения и SHA‑256 DMG, macOS и архитектуру. Для Mac-приёмки используйте установленный DMG. Прогоны через браузер указывайте как отдельную среду.
2. Используйте одноразовый профиль и тестовый проект. Для независимой попытки создайте пустое дерево и новый чат. Включите только нужный кейсу контекст. Для синтетических кейсов выключите веб-поиск. Ключи и существующие логины подключаются обычным способом через настройки.
3. Выберите точный backend, модель и reasoning для чата и Suggested KPI. Запишите выбор в отчёт. Смена модели или провайдера считается новой попыткой.
4. Отправьте текст из [requests.md](requests.md). Подтверждайте только обычные продуктовые решения и сообщайте только доступные факты. Сохраняйте уточнения, повторы, ошибки и длительность каждой попытки. Прогон с подсказанной формулой или исправленным оператором деревом считается диагностическим.
5. При завершении сохраните итог, ID прогона и ревизии, дерево с формулами и единицами, выбранные скиллы и результат повторного открытия. Для файла добавьте хеш исходника, таблицу, знаменатель и покрытие строк. Пробное изменение сделайте после оценки исходного результата в сценарии или копии дерева. Контрольные значения сверяйте по [эталонам](oracles.md).

Одна строка отчёта соответствует одной попытке. Поля — кейс, коммит, среда, исполнитель, backend, версия CLI, модель, reasoning, длительность, статус, ожидаемый и фактический результат, ID прогона/ревизии и ссылка на доказательство. Храните отчёты, снимки и безопасные журналы вне Git. Перед передачей удаляйте из них ключи и данные аккаунта.

- **PASS** — выполнены условия кейса, есть доказательство сохранения или ожидаемого отказа.
- **FAIL** — результат, расчёт, сохранение или поведение отличаются от эталона.
- **BLOCKED** — прогона не было из-за среды, отсутствия CLI, доступа к аккаунту или функции в сборке. Укажите точную причину.
- **SKIP** — сценарий или сочетание провайдеров исключены из объявленного объёма выпуска. Укажите решение в отчёте.

Для полного агента отметьте, был ли подтверждён сохранённый результат. При доступном read-only захвате приложите снимок прогона и активную ревизию. Методика [независимой оценки](../../docs/AGENT_EVALUATION.md) описывает, как отделить естественный сценарий от диагностики с подсказками.

Создать простое дерево с ручным значением, закрыть приложение, запустить снова. | Gatekeeper пропускает подписанное приложение, оно стартует офлайн, значение и ревизия сохраняются. Зафиксированы исходный и новый результаты. |

Для MAC-01 подставьте фактический путь скачанного образа и проверьте скопированное приложение.

```bash
shasum -a 256 "$VDT_QA_DMG"
xattr -p com.apple.quarantine "$VDT_QA_DMG"
xcrun stapler validate "$VDT_QA_DMG"
spctl --assess --verbose=4 --type execute "/Applications/VDT Studio.app"
codesign --verify --deep --strict "/Applications/VDT Studio.app"
```

Для MAC-02 подготовьте отдельный профиль по [инструкции установки](../../docs/desktop-installation.md#local-apple-silicon-alpha). Обе версии должны использовать одну тестовую копию данных. Запишите исходные значения и хеш файла до замены приложения.

## Построение дерева

Укажите целевой KPI и период из запроса при создании пустого дерева. В основном прогоне TREE-01–TREE-04 закрепите указанный скилл в контексте и убедитесь, что сохранённая попытка ссылается на его ID и версию. TREE-03 и TREE-04 повторите без закрепления для проверки автоматического выбора. Для TREE-05 и TREE-06 оставьте выбор открытым. Применение Universal Skill или обоснованное построение без предметного скилла допустимо.

| ID | Цель и контекст |
| --- | --- |
| TREE-01 | Экскавация руды за смену. `mining.excavation`. |
| TREE-02 | Карьерная перевозка руды за смену. `mining.haulage_truck_cycle`. |
| TREE-03 | Выручка от отгрузки за месяц. `finance.revenue_profit`. |
| TREE-04 | Новый MRR из воронки. `saas.funnel_growth`. |
| TREE-05 | Часы эскалаций службы поддержки за месяц. Предметного скилла нет. |
| TREE-06 | Суточная пропускная способность последовательного участка. Предметного скилла нет. |
| TREE-07 | Исходный запрос по чистой выручке. Для сравнения с закрытой альфой повторить трижды на OpenAI Direct `gpt-5-nano` / Low. |
| TREE-08 | Неполные данные по отгрузке. Уточнить недостающую цену, затем проверить итог. |

Проверьте итог и контрпример по [эталонам деревьев](oracles.md#деревья). Эквивалентная формула и обоснованные промежуточные расчёты допустимы. Обязательны исходные измерения, корректные единицы, объяснимая связь с корнем и реакция на изменение входа. Зафиксируйте повтор одной и той же просьбы, лишние дубли KPI или расхождение сообщения с сохранённым итогом.

## Импорт простоев

Период для всех файлов — **2–5 ноября 2026 включительно**, четыре календарных дня. В журнале одной линии 5 ноября нет событий. Знаменатель включает этот день. Цель — «Средний простой» с единицей `h/day`. При сопоставлении поле даты служит описанием исходника. Группируйте по виду простоя. Сумма часов за период делится на четыре, без округления отдельных событий или групп.

Для FILE-01–FILE-05 откройте пустое сохранённое дерево, выберите корень → **From file** и загрузите указанный файл. Дождитесь анализа провайдером. Зафиксируйте первоначальное предложение таблицы, колонок и единиц. Если требуется, подтвердите настройки ниже в review. Для валидного файла проверьте покрытие, затем выполните **Stage → Patch ready → Apply**. Закройте и откройте дерево, сравните числовой итог, формулу корня и происхождение каждого KPI. Для отрицательного кейса остановитесь на отклонении и убедитесь, что активная ревизия и граф остались прежними. [Контракт From file](../../docs/DATA_INGESTION.md#current-flow)

## Провайдеры

Начните с подключения. Для CLI используйте страницу **Your subscriptions**, обнаружение исполняемого файла, проверку авторизации и Test. Для OpenAI Direct используйте **Test connection** и явно выберите модель. Затем выполните кейсы в установленном приложении. Запишите фактические параметры из интерфейса и сведения о запуске.

| Backend | Приёмка в приложении |
| --- | --- |
| OpenAI Direct | Полный набор деревьев, Smart и файлов на `gpt-5-nano` / Low. Повторить провалившийся сценарий на другом выбранном режиме отдельной попыткой. |
| Codex CLI | TREE-01, TREE-02, TREE-05, TREE-07, SMART-01, FILE-01 и FILE-06. |
| Cursor Agent | TREE-02, TREE-03, TREE-04, TREE-06, TREE-07, SMART-01, FILE-01 и FILE-06. |
| Claude Code и GitHub Copilot CLI | После обнаружения и входа выполнить TREE-02, TREE-05, SMART-01 и FILE-01. Проверять FILE-06 для провайдера, если заявляется полный чат с файлами. |
| OpenCode, Hermes, Kiro, Kimi, Mistral Vibe, Kilo, Qwen, Grok и Pi | Записать установку, доступ, версию и модели. При наличии авторизованного подключения повторить минимальный набор по заявленным возможностям. |

Команды ниже запускают проверку адаптера на исходниках с Node 24 и установленными зависимостями. Первая проходит весь каталог. Вторая проверяет один backend с явно выбранной моделью и включает генерацию минимального дерева. Укажите модель, доступную в текущем каталоге CLI.

```bash
corepack pnpm exec tsx scripts/live-subscription-cli-smoke.mjs --backend all --connection-only
corepack pnpm exec tsx scripts/live-subscription-cli-smoke.mjs --backend codex_subscription --model gpt-6-luna
corepack pnpm exec tsx scripts/live-subscription-cli-smoke.mjs --backend cursor_subscription --model composer-2.5
corepack pnpm exec tsx scripts/live-subscription-cli-smoke.mjs --backend claude_subscription --connection-only
corepack pnpm exec tsx scripts/live-subscription-cli-smoke.mjs --backend copilot_subscription --connection-only
```

Для отдельной диагностики планировщика Codex/Cursor предусмотрен `scripts/live-agent-cli-smoke.mjs` с фиксированным сценарием перевозки и ответами на вопросы. Результат такого прогона учитывается отдельно от живых кейсов установленного приложения. Подключение, структурированная генерация, сохранённое дерево, Smart и импорт получают отдельные статусы. [Каталог и условия авторизации CLI](../../docs/HARNESS_CONNECTIONS.md)

## Проверка файлов без провайдера

```bash
corepack pnpm exec tsx eval/open-alpha/verify-downtime.mjs
```

Команда читает исходники через парсер VDT, применяет явные настройки импорта и сверяет рассчитанные значения с отдельным эталоном. Положительные сценарии проверяют применение формулы и источник. Код выхода 2 и результат `FILE-05 FAIL` означают, что дубликат не блокирует импорт. Код 1 означает сбой проверки или несоответствие другого сценария. Отчёт команды относится к детерминированному импорту и используется вместе с живыми кейсами.
