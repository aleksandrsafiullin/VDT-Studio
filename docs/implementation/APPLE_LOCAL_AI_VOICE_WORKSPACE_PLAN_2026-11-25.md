# Apple on-device AI, voice and factor-tree authoring

**Implementation plan for the GPT-6.2 Astra orchestrator · 25 November 2026 · Proposed**

A new user opens VDT Studio on a compatible Mac and can immediately ask the on-device Apple model to build a factor tree. The same user can speak a follow-up, answer a question, correct a KPI in the editor and request a named scenario workbook. A professional can use the same operations with a subscription CLI, an API key or another local model of their choice. Each route must produce a tree the user can inspect, change, save and reopen.

The first release covers local analytics and half-duplex voice. The analytical model, speech recognition and speech synthesis are three independently discoverable capabilities. Apple is the first-install analytical default when the system model is ready and the shipped integration has passed the gates below. Microphone capture and automatic speech start only when the user enables them.

### Orchestrator instructions

Use the [implementation prompt](APPLE_LOCAL_AI_VOICE_ORCHESTRATOR_PROMPT_2026-11-25.md) to start the orchestrator.

1. Use English for execution, agent communication, progress updates, repository documentation, reviews and the detailed engineering handoff. Give the user a concise final task status in Russian. Preserve the language of product interactions, user input and bilingual fixtures.
2. Astra owns contracts, ordering, integration and final acceptance. Give each ready ticket to one Sol-class implementer. Include the goal, permitted write scope, dependencies, fixture, expected observable result and checks. A second agent reviews the diff and evidence independently. Return findings to the owner, then rerun the affected gate. Serialize edits to shared schemas, provider registries and Supervisor files.
3. Maintain a compact ledger during implementation with ticket, owner, base commit, status, changed paths, command/fixture, evidence location, reviewer and remaining blocker. Use separate entries for deterministic, live model, real microphone and installed-app evidence. Preserve failed attempts as well as retries. Continue independent work if hardware, permissions, credentials or an external entitlement block one lane.
4. Follow repository and Mac build rules. Check free space on the actual build and temporary volumes before heavy jobs. Below 10 GiB, report the blocker. Give each Xcode build/test its own `mktemp -d` directory and `-derivedDataPath`, each test its own `-resultBundlePath`, and default to `-parallel-testing-enabled NO`. Preserve required diagnostics before removing owned artifacts, wait for child processes and report cleanup and retained large files. Use disposable workspaces for fixtures.
5. An implementation ticket authorizes only its scoped work. Model/asset downloads require the documented consent flow. Use already-authorized accounts and budgets for live tests. Keep purchases, global configuration changes, public release and real user project changes under the user's control.

## Acceptance fixtures and expected results

### First launch through a saved tree

1. Launch the installed app on an eligible Mac with system assets ready and no saved provider preference. Confirm Apple is selected before the first request. Leave the goal picker on Automatic, the Skill picker untouched and network access disconnected. Start in text once and repeat in an explicitly enabled voice session on a fresh project.
2. A novice asks for a tree of two production stages and says measurements will come later. The agent clarifies how material flows through the stages. Once serial flow and compatible capacity units are confirmed, it saves and reopens a structure with two unknown capacities. A verified structure receipt identifies the missing inputs.
3. Supply 70 and 90 t/h. For the explicitly confirmed simple serial-capacity case, output is 70 t/h. Ask about raising the second stage to 100 t/h. Output remains 70 t/h. Repeat with confirmed independent additive parallel flows. Those same numbers give 160 then 170 t/h. Include ambiguous and out-of-domain controls so a label or industry name cannot determine the formula.
4. Define the KPI in everyday language. Reopen the conversation, correct the definition and continue. The latest definition has traceable user evidence. A second VDT does not inherit it. Repeat with a genuine zero, which persists as zero.
5. In the professional fixture keep Baseline selected while requesting the Recovery workbook. Edit downtime from 100 to 110 h while restore approval is pending. The old approval is rejected, the correction survives reopen, Baseline is 1,780 t and Recovery is 1,820 t. A single requested named version and a downloadable workbook identify the actual Recovery revision. Inspect the exported cells/formulas and recalculate after an input edit.
6. Select another available local model, CLI subscription or API key for a new run. Verify the chosen binding after restart, including an independently chosen Smart model. Switching while speaking closes incompatible audio and preserves the draft. It cannot turn a local run into a paid run. Disabling Apple Intelligence exposes recovery and leaves the manual editor, calculation and file preview usable.
