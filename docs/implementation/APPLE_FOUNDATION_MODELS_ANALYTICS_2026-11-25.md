# A03 Apple analytical preview

The Apple model is exposed only when the packaged desktop host verifies and
injects the fixed native helper path and SHA-256. The preview enablement gate
is off by default. App deployment, first-launch activation and signed offline
qualification have separate gates.

## Selection and authority

The existing packaged-web authentication and exact same-origin binding route
admit an explicit locale. The host binds `apple_foundation_models` /
`SystemLanguageModel.default` to the public SDK variant, observed OS build,
runtime profile, locale and 8,192-token budget. The OS supplies no internal
digest, so the model revision remains unknown. A version or locale change
requires fresh admission. The host rechecks readiness before start,
continuation and every bounded request. Stale identity, busy, timeout,
context overflow, refusal and invalid proposals stop the Apple route without
starting a different provider.

The normal composer offers a temporary Apple preview choice when the trusted
host advertises enablement. The chat selector and bounded host share one Node
process owner, which dispatches private Swift child requests. Authenticated
same-origin HTTP covers the existing webview-to-host leg. The Apple helper
itself has no HTTP listener. The static desktop sidecar route does not
advertise Apple support.

The Supervisor projects only the current stage's operation list, a compact
workspace observation and the original brief, confirmed conversation facts
and selected Skill. Apple proposes a single operation and canonical
arguments. The host validates that shape and the existing Gateway owns
approval, deterministic verification, exact revision and all mutation
authority. No research, delegation, private cloud, or provider fallbacks run
under this binding. Skill resolution and approval use the same real Gateway
paths as the other model engines.
