# Apple Suggested KPI validation follow-up

This check uses the normal explicit Smart preparation route and the selected
Apple binding. The preview has one native execution owner. Speculative
preparation does not occupy it. Request admission and Smart validation continue
to use the current target, selected Skill, model identity and revision checks.

The bridge previously surfaced `invalid_output` both when the native helper
failed to produce a proposal and when Node rejected the canonical response.
The route now distinguishes those stages without exposing the generated text,
tree content, credentials or native diagnostic details.

| Stable outcome | Meaning |
| --- | --- |
| `invalid_output` | The native helper failed to supply a usable structured response. |
| `APPLE_SMART_ENVELOPE_INVALID` | Node rejected the outer guided envelope. |
| `APPLE_SMART_GROUP_SHAPE_INVALID` | The group exceeded the supported shape or factor bound. |
| `APPLE_SMART_CANONICAL_INVALID` | The existing Smart validator rejected the projected result. |

Controlled normal-route fixtures distinguish these cases, preserve the exact
model identity, period and target, and carry through a complete group with
its original formula and referenced child IDs. They also verify that an
invalid attempt makes no alternate-provider request.

The candidate removes the JSON string nested inside a guided string.
It guides a single layer's title, formula and bounded factor records directly.
The adapter supplies the canonical group ID and lists every factor key as
required. The existing validator still rejects inconsistent formulas, invalid
factor IDs, incomplete groups and unapproved recipe or target relationships.
No model text is used as tool, Apply or revision authority.

The retained earlier normal-route attempt `a03/live-v6-null.json` returned
`invalid_output` after 13.5 seconds. That receipt predates stage diagnostics
and cannot identify the rejection layer. The controlled route fixtures pass
for the new guided candidate.

The first controlled live run of the revised Smart preparation route
(`a03/smart-live-typed-v1.json`) used a verified signed preview helper with
`SystemLanguageModel.default`, `en-US`, and macOS 27.0.1 build 26A434.
The route returned HTTP 504 `TIMEOUT` after 15,005 ms at a 15,000 ms
request deadline. No proposal reached the Node validators and no KPI group
was returned. The run used an in-process workspace route with the signed
helper and disposable data, which were removed after the test. Live quality,
latency and installed-app behavior remain unqualified.

The focused adapter checks also cover an explicitly defined
two-stage target on a known unit basis. The same scope check supplies
first-prompt guidance and validates each ready result. For a continuous
material stream with two independent stage-capacity measurements, it asks
for two blank inputs and their minimum. For ambiguous descriptions, the
general guidance applies. An explicit empty proposal stays a valid
terminal response. All proposals still pass the canonical validation and
the ordinary review and Apply path.

The compact serial guide is limited to the exact bundled generic Skill
and a two-stage target with a declared common unit basis and no applicable
recipe, plan or reusable inputs. The guide offers two measured factors
and a minimum, or an empty result with a reason. Live preparation on the
network-denied source route used the exact signed Apple helper and
returned one group with two blank t/h inputs and their minimum in one
generation. Two independent arithmetic probes gave 70 t/h for opposing
70 and 90 t/h stage capacities. The saved head remained unchanged during
Prepare. The live call used 2,448 input tokens and 1,000 reserved output
tokens in an 8,192-token context. Installed Apply and whole-system offline
qualification are recorded separately in the execution ledger.

The Apple adapter now uses the guided variant of the shared Smart instructions.
The variant keeps the modeling rules and replaces the legacy JSON envelope
directions. A second controlled live run used the same production-volume root,

(`a03/smart-live-guided-v2.json`), compared with 15,005 ms for the previous
